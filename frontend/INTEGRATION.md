# Meditron: подключение фронтенда к FastAPI

Фронтенд на JavaScript + Vite. Исходники — `src/`, страницы — `src/pages/`, общие компоненты — `src/components/`, стили — `src/styles.css`, маршруты — `src/router.js`. Запуск: `npm run dev`, затем http://localhost:5173. Проверки: `npm test`. Сборка: `npm run build`.

## 1. Настройка

Скопируйте `.env.example` в `.env`. Задайте `VITE_USE_MOCKS=false`, `VITE_API_URL=https://ваш-api`, `VITE_REQUEST_FORMAT=labs` или `features`. При локальной разработке допустим `http://localhost:8000`. Перезапустите Vite после изменения .env. Переменные с префиксом VITE_ доступны браузеру: секреты в них помещать нельзя. Раздел «Подключение API» позволяет временно поменять режим, адрес, формат и маршрут, а также проверить `/health`. Значения в этом разделе не сохраняются после обновления страницы.

Опубликованная HTTPS-страница требует HTTPS API. В CORS FastAPI добавьте точный origin опубликованного сайта, localhost:5173 для локальной разработки, разрешённые методы и заголовки Content-Type и Authorization. Не включайте wildcard для приватного API. Фронтенд не содержит ключей или путей к моделям.

Пример конфигурации CORS (замените домен):

```python
from fastapi.middleware.cors import CORSMiddleware
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173", "https://meditron-screening.terracopter695.chatgpt.site"],
    allow_credentials=False,
    allow_methods=["GET", "POST", "OPTIONS"],
    allow_headers=["Content-Type", "Authorization"],
)
```

## 2. Модули

| Файл | Назначение |
|---|---|
| src/api/client.js | fetch, Bearer token, timeout, HTTP и сетевые ошибки |
| src/api/screening.js | преобразование формы, валидация ответа, запуск скрининга |
| src/api/auth.js | вход, регистрация, текущий пользователь, выход |
| src/api/history.js | история, динамика, пакетная загрузка |
| src/mocks/screening.js | фиксированный демонстрационный ответ и история в памяти |
| src/types/screening.d.ts | описания типов для дальнейшего переноса в TypeScript |
| src/catalog.js | предварительный список показателей, единиц и русских названий |

fetch не вызывается в UI. Mocks подключаются только в API-модулях. Фронтенд не выполняет ML, нормализацию, imputation, расчёт риска или диагностику.

## 3. Схема скрининга — предварительная, сверить с backend

Основной маршрут `POST /api/v1/screenings`, настраивается в src/config.js. Формат labs:

```json
{
  "age": 22,
  "sex": "female",
  "symptoms": "Описание самочувствия",
  "labs": [
    {"code":"hemoglobin","value":132,"unit":"g/l"},
    {"code":"ferritin","value":16,"unit":"ng/ml"}
  ]
}
```

age, sex и symptoms включаются только при заполнении. Если API их не поддерживает, удалите соответствующие поля из makePayload в src/api/screening.js. Поддержка текста как второй модальности зависит от сервера; фронтенд не утверждает наличие мультимодальной модели.

В режиме features тот же контекст отправляется с `features: {"hemoglobin":132,"ferritin":16}`. Этот режим не передаёт единицы: сервер должен иметь фиксированный, согласованный с каталогом набор единиц. Пустые поля исключаются из запроса; ноль сохраняется как число. Десятичная запятая поддерживается. Числа проверяются на конечность и неотрицательность. Клинические ограничения и минимальный набор показателей проверяет API. Возраст в форме — от 0 до 120; применимость модели к возрастным группам определяет сервер.

Ответ может быть плоским:

```json
{
  "predicted_class": "iron_deficiency",
  "confidence": 0.87,
  "probabilities": {"iron_deficiency":0.87,"vitamin_d_deficiency":0.21},
  "top_features": [{"feature":"ferritin","importance":0.64}],
  "quality_warnings": [],
  "model_version": "1.0"
}
```

Также поддерживается envelope с `id`, `created_at` и `result`. confidence и probabilities: числа от 0 до 1. predicted_class — строка. Остальные поля необязательны. Неизвестные классы и показатели отображаются своим API-кодом; дополните словари catalog.js для русских названий. Проценты подписаны как оценки модели, а не как подтверждённая вероятность заболевания. Порог риска не выдумывается.

## 4. Авторизация — маршруты предварительные

| Метод | Маршрут | Договорённость фронтенда |
|---|---|---|
| POST | /auth/register | JSON {email,password}; после успеха показывается вход |
| POST | /auth/login | JSON {email,password}; ответ {access_token,token_type} |
| GET | /auth/me | ответ {id,email,role?}; роли patient / doctor |

Если FastAPI принимает OAuth2 form-urlencoded с username, измените login в auth.js. Сейчас предполагается JSON. Токен хранится в памяти, автоматически добавляется `Authorization: Bearer ...`; после обновления страницы нужен повторный вход. Пароли не сохраняются. Демовход не аутентифицирует пользователя и не создаёт аккаунт. Пользователь не может назначить себе роль врача в интерфейсе; её возвращает /auth/me. Проверка прав и владения каждой записью обязательна на бэкенде.

## 5. История

`GET /me/screenings` → массив записей либо `{items:[...]}`:

```json
{
  "items": [
    {
      "id":"123",
      "created_at":"2026-10-04T09:00:00Z",
      "labs":[{"code":"ferritin","value":26,"unit":"ng/ml"}],
      "result":{"predicted_class":"iron_deficiency","confidence":0.67}
    }
  ]
}
```

При live-скрининге фронтенд не сохраняет запись самостоятельно: POST /screenings должен сохранить её на сервере для авторизованного пользователя. Если нужны отдельная команда сохранения, пагинация или иной envelope, измените history.js. Защищённые страницы требуют входа. Демонстрационная история существует в памяти и очищается кнопкой; повторное открытие страницы восстанавливает seed-пример.

## 6. Динамика

Предлагаемый маршрут `GET /me/lab-trends` ещё не подтверждён. Настраивается в src/config.js. Ответ: массив или `{items:[...]}`:

```json
{
  "items":[{
    "code":"ferritin",
    "unit":"ng/ml",
    "points":[{"date":"2026-08-01","value":12},{"date":"2026-09-01","value":19}],
    "reference_low":15,
    "reference_high":150,
    "reference_source":"Диапазон лаборатории для конкретного пациента"
  }]
}
```

Числа в этом примере условные, не универсальная норма. Референсные значения необязательны. Графики строят линии только при получении диапазона; фронтенд не назначает нормы в live-режиме. Сервер учитывает пол, возраст, лабораторию и единицы. Измерения разных единиц нельзя объединять в одну серию без серверного преобразования. В demo история группируется по code и unit отдельно. Данные всех точек доступны в таблице под графиком.

## 7. Врач и CSV

Раздел /#/doctor: выбор файла и drag-and-drop, ограничение 5 МБ, CSV UTF-8, предварительный просмотр первых 10 строк, поддержка кавычек и разделителей `,` / `;`. Нужна колонка patient_id. Пример можно скачать прямо в разделе. Это предварительный просмотр, не медицинская валидация и не проверка соответствия backend schema.

В src/config.js `endpoints.batch` по умолчанию null. После согласования установите путь; запрос использует multipart/form-data, поле `file`. Кнопка отправки доступна только в live-режиме с настроенным endpoint. Ответ пока отображается как JSON; после утверждения batch response schema добавьте таблицу результатов. XLSX намеренно пока не поддерживается; UI честно сообщает об этом. Обязательную проверку роли doctor, формата, лимитов, идентификаторов пациентов и доступа выполняет сервер.

## 8. Ошибки и состояние

Пустое состояние, загрузка, успех, ошибки формы, 400/401/403/404/422/429/500/502/503, отсутствие соединения, timeout 30 секунд. Повторный submit скрининга блокируется на время запроса. При уходе со страницы поздний ответ не заменяет текущий экран. У 401 очищается пользовательская сессия. Текст backend ошибок не выводится без фильтрации в HTML. Поле ApiError.details сохраняет detail от FastAPI; для привязки к конкретным полям нужно добавить mapping loc → name.

## 9. Экспорт

«Печать / PDF» открывает стандартное окно печати браузера — выберите «Сохранить как PDF». Это не серверная генерация отчёта. JSON экспортирует отображаемую запись, вместе с маркировкой demo, если она тестовая.

## 10. Перед интеграцией команда API фиксирует

- Окончательные маршруты, Pydantic request/response и OpenAPI.
- Поддерживаемые codes, единицы, обязательные поля, обработку пропусков.
- Контекст age/sex/symptoms и фактическую поддержку второй модальности.
- Семантику confidence, probabilities и top_features; ограничения модели.
- JSON vs OAuth2 login, механизм токена и роли.
- Сохранение скрининга, историю, пагинацию, референсные диапазоны.
- CSV/XLSX формат, batch endpoint и формат ответа.
- HTTPS, CORS, серверную авторизацию и правила обработки данных.

## Проверка и ограничения

API-тесты проверяют пропуски, нули, два формата request, корректность response, HTTP 422, таймаут, сетевую ошибку, авторизационный заголовок. Проверен синтаксис всех JS-модулей. Дополнительно пройдены DOM-проверки потока: пустая форма, дробь с запятой, ответ, история, графики, несовпадающие пароли и CSV с кавычками. Визуальная QA в реальном браузере не выполнена. Реальный API ещё не предоставлен, поэтому интеграция с работающей моделью не проверена. Перед демонстрацией проверьте форму, PDF-печать и мобильную версию в браузере, затем подключите настоящий API и выполните полный поток.
