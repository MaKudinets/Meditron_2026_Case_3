# Meditron — frontend

Самостоятельная папка frontend для репозитория meditron_2026. Интерфейс на русском, JavaScript + Vite, фирменные цвета и IBM Plex Sans/Mono, иллюстрации Meditron. Без React: для текущего прототипа достаточно обычных модулей JavaScript. Описания API-типов находятся в .d.ts; приложение пока не является TypeScript-проектом.

## Первое действие ответственного за frontend

1. Распакуйте архив: папку `frontend` положите в корень `meditron_2026`, рядом с `api` и `ml`.
2. Если frontend уже существует, сначала сравните файлы; переносите изменения отдельной веткой, не удаляя работу команды.
3. Откройте `frontend` в VS Code. Установите Node.js 22.12+ или более новую совместимую LTS-версию.
4. Откройте терминал в этой папке, выполните `npm ci`.
5. Скопируйте `.env.example` в `.env` средствами редактора. Для первого запуска оставьте `VITE_USE_MOCKS=true`.
6. Выполните `npm run dev` и откройте http://localhost:5173.
7. На странице скрининга нажмите «Заполнить пример», подтвердите ознакомление с условиями и запустите скрининг. Откройте результат, историю и динамику.

Демонстрационный ответ заранее задан и не является медицинским расчётом. Деморегистрация не создаёт настоящий аккаунт. Данные demo и токен находятся в памяти страницы до обновления; пароли в хранилище не записываются.

## Команды

```bash
npm ci
npm run dev
npm test
npm run build
npm run preview
```

`dev` — разработка; `test` — API и DOM проверки; `build` — production-файлы в dist; `preview` — просмотр сборки на http://localhost:4173. `npm run format` форматирует исходники. node_modules, dist и .env не нужно коммитить.

## Страницы

Главная, о сервисе, как это работает, новый скрининг, результат, вход, регистрация, кабинет, история, динамика, раздел врача, условия обработки данных, подключение API и неизвестный маршрут. На странице результатов есть экспорт JSON и печать через диалог браузера, включая «Сохранить как PDF».

## За что отвечает frontend-разработчик

- Удобная форма: подписи, единицы, необязательные показатели, корректные числа, состояние кнопки.
- Преобразование формы в точную Pydantic-схему API через makePayload.
- Отображение всех возвращаемых состояний и предупреждений без собственных диагнозов и порогов.
- Загрузка, повторный запрос после ошибки, пустые состояния, вход и выход.
- Согласование CORS, адресов и форматов с backend-разработчиком.
- Проверка в настоящем браузере на компьютере и мобильной ширине.

Обучение модели, imputation, нормализация, клинические ограничения, права доступа, сохранение анализов и выбор референсных диапазонов выполняются сервером.

## Что получить от backend прямо сейчас

Попросите OpenAPI JSON или примеры из Swagger `/docs`:

1. Точные URL и JSON запроса/ответа скрининга.
2. Полный список codes, единицы, обязательные поля и правила пропусков.
3. Поддерживаемые age, sex, symptoms. Текстовый блок интерфейса не гарантирует, что сервер умеет обрабатывать вторую модальность.
4. Маршруты и формат login/register/me, JSON или form-urlencoded, схему роли врача.
5. Формат истории и факт сохранения POST-скрининга на сервере.
6. Формат динамики и референсных диапазонов.
7. Адрес API и разрешённый CORS origin.
8. Если нужен пакетный режим — маршрут, файл CSV/XLSX, имена колонок и формат ответа.

Это точки согласования, а не утверждение, что все такие endpoints уже реализованы.

## Подключение к работающему API

В .env:

```dotenv
VITE_API_URL=http://localhost:8000
VITE_USE_MOCKS=false
VITE_REQUEST_FORMAT=labs
```

Перезапустите dev-сервер. Сначала проверьте `/health` в разделе «Подключение API», затем отправьте один обезличенный тестовый анализ. При несовпадении схемы измените только соответствующий src/api модуль и каталог. Основной endpoint настроен как POST /api/v1/screenings. Форматы labs/features поддерживаются адаптером. Если поля контекста не принимаются сервером, удалите их из makePayload до реальной интеграции.

Для публикации нужен HTTPS API. Для localhost требуется CORS на http://localhost:5173. Подробный пример FastAPI CORS и все предварительные схемы — в INTEGRATION.md.

## Последовательность работы команды

1. Локальный запуск и просмотр всех страниц на mocks.
2. Утверждение схем с backend.
3. Один настоящий POST скрининга и корректное отображение ответа.
4. Проверка отсутствующих показателей, ошибок 422, недоступного API и повторного запроса.
5. Авторизация и история, если endpoints действительно готовы.
6. Динамика на настоящих данных и ranges от сервера.
7. Пакетный режим врача только после утверждения batch API.
8. Проверка настоящего браузера и сборка npm run build перед демонстрацией.

Не тратьте первый этап на реализацию дополнительных endpoint на фронтенде. Основной путь — форма → API → результат — должен пройти с живым сервером первым.

## Проверено

Установка зависимостей, production-сборка, преобразование пропусков и нуля, оба request формата, валидация response, Bearer, HTTP 422, сетевые ошибки, timeout, DOM-поток формы с десятичной запятой, результат, история, графики, подтверждение пароля, CSV с кавычками. Реальная модель не подключена, визуальная проверка в браузере не выполнена.
